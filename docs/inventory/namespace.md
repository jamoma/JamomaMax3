# Namespace: node creation, instances and removal (characterisation)

Read from the old checkout (`~/Developer/Jamoma/JamomaMax/JamomaCore`). "Read" = I read the code. These rules are the source of truth for `core/tests/namespace_test.cpp`.

## Creating a node (`Foundation/library/source/TTNodeDirectory.cpp`, `TTNodeCreate`, line 231)

1. The address is normalised (directory and attribute removed).
2. If **no node exists at that address** (`name` plus instance), the node is created with the instance given in the address (an explicit `name.4` keeps 4). *Read.*
3. If a node **already exists at that address**, a new instance is generated by `generateInstance` and the new node gets that instance. *Read.*
4. Missing ancestors are created first as container nodes without an object, taking their instances from the address (`TTNode::setParent`, `TTNode.cpp:~210`). *Read.*

## Generated instance numbers (`TTNode.cpp:578`, `generateInstance`)

The new instance is the **first number from 1 upward that is not in use** among the existing instances of that name under the same parent (the node with no instance is not a number and does not block 1). A number freed by a removal is therefore reused. *Read.*

Consequences used in the tests: `p`, then `p.1`, then `p.2`; an explicit `p.4` that is free stays `p.4`; an explicit `p.4` that is taken becomes the first free number (`p.1`, not `p.5`); after `p.1` is removed the next duplicate is `p.1` again while `p.2` keeps its number.

## Subscribing an object (`Modular/library/source/TTSubscriber.cpp:78-135`, `Subscribe`)

Looks up the absolute address:
- **no node** -> create it (rule 2); not a new instance;
- **node without an object** -> attach the object to the existing node (notifies observers of the creation); not a new instance;
- **node with an object** -> create another instance (rule 3); `newInstanceCreated` is true.

The subscribed node's address is then reported back (relative to the context node). *Read.*

## Removing a node (`TTNodeDirectory.cpp`, `TTNodeRemove`, and `TTSubscriber::Unsubscribe`)

- Unsubscribing an object whose node has **no children** removes the node; a node **with children** only loses its object (observers are notified of the unregistration). *Read.*
- After a removal, the **parent is removed too if it has no children and no valid object**, recursively upwards (the root is never removed). *Read.*

## Differences chosen on purpose

- Observers (`kAddressCreated` / `kAddressDestroyed`) are not part of this milestone's API; `j.receive` (milestone 2) adds them.
- A `Node*` handed out by `lookup` is valid only while the node exists; callers must not keep it across unsubscribing.
